Ocean OS / Architecture overview
source-grounded · 2026-06
local-first agent operating layer

One daemon, many cockpits, one shared Rust-native brain.

Ocean OS is a Rust monorepo for a long-lived local agent daemon, permissioned runtime, multi-provider model protocol, workspace-bound sessions, browser tools, and thin clients. Ocean Surface is the sibling client-face repo: Leptos web/PWA, voice, Chrome side panel, and the native GPUI desktop app.

Current crate map

What exists in the workspace today.

Grounded in Cargo.toml, README.md, and docs/ARCHITECTURE.md.

01

Core protocol

ocean-core holds shared wire/session/event types. ocean-agent-sdk exposes the embedding surface.

02

Agent authority

ocean-daemon, ocean-agent, and ocean-runtime own turns, tools, sessions, permissions, and event mapping.

03

Model layer

ocean-protocol and ocean-providers route OpenAI-compatible, Anthropic, Google, DeepSeek, and credential readiness.

04

Operator clients

ocean-tui is the ratatui steering cockpit. ocean-cli is the one-shot/control client. The sibling ocean-surface/crates/ocean-gui is the native GPUI desktop shell.

05

Browser layer

ocean-browser wraps Chrome DevTools Protocol. Runtime browser tools expose page read, screenshot, clicks, typing, JS, console, and network.

06

Longhouse coordination

LonghouseEvent rides the existing agent event bus as Extension payloads. The standalone deck renders non-hierarchical agent coordination as a living underwater building.

07

Interop

ocean-mcp and ocean-acp sit in the workspace for external agent/protocol integration paths.

Product API

The stable surface between brain and cockpits.

The current contract is explicit: Project → Workspace → Session → Turns → Events, and every first-party surface attaches to a session before submitting turns.

POST /v1/agent/sessions
{
  "cwd": "...",
  "project_id": "...",
  "client_type": "surface-web"
}

GET /v1/agent/events?session_id=<id>
POST /v1/agent/turns
{
  "session_id": "...",
  "prompt": "...",
  "client_type": "surface-web"
}

# legacy/debug only
GET /v1/agent/events

Defined hierarchy

Project is the durable product identity; Workspace is a concrete checkout or local directory; Session is one agent/human work thread rooted in exactly one workspace; Surface is a UI attached to a session.

Source: docs/OCEAN_ECOSYSTEM_CONTRACT.md:5-23, docs/OCEAN_ECOSYSTEM_CONTRACT.md:25-43

No global adoption

First-party clients must not adopt active sessions from the global SSE stream. Cross-surface sharing is explicit: two surfaces subscribe to the same session_id, or they stay isolated.

Source: docs/OCEAN_ECOSYSTEM_CONTRACT.md:17-23, docs/OCEAN_ECOSYSTEM_CONTRACT.md:42-43
