Ocean OS / Daemon
slice 3 · daemon
local HTTP + SSE authority

The daemon is the shared brain process behind every Ocean cockpit.

ocean-daemon is the long-lived service that binds locally, owns the runtime instance, broadcasts events, tracks cancellable requests and permission waits, and exposes the product API used by the TUI, CLI, Ocean Surface, GPUI shell, voice, and browser extension.

Process shape

What starts when the daemon boots.

The service is small, but it centralizes authority that clients should not duplicate.

01

Runtime from env

AgentRuntime::from_env()?.with_extensions().await constructs the provider/tool runtime and folds configured MCP extensions into the capability registry.

Shared state

AppState holds the runtime plus two broadcast buses: legacy OceanEvent and product-shaped AgentTurnEvent.

03

CORS + router

The daemon accepts local web clients with broad CORS and mounts HTTP routes for agent turns, sessions, requests, permissions, projects, models, components, and Longhouse demo events.

Turn lifecycle

One submitted turn becomes a typed event stream.

This is the daemon-side bridge from runtime events to client-renderable product events.

Session and cwd are resolved first

POST /v1/agent/turns rejects turns that cannot resolve a working directory. A non-empty cwd wins; otherwise project_id can resolve to a project workspace. This avoids silently falling back to the daemon launch directory.

Source: crates/ocean-daemon/src/main.rs:1769-1787

Room guidance is daemon-injected

The optional room_id is parsed for Track-0 rooms such as pm, writers, orch_mesh, and review; valid rooms prepend guidance to the prompt before runtime execution.

Source: crates/ocean-daemon/src/main.rs:1808-1840, :2067-2082

The turn id is the cancellable request id

The daemon registers the turn with a cancellation token and threads that token through PromptControl. Client halt controls use POST /v1/requests/{turn_id}/cancel.

Source: crates/ocean-daemon/src/main.rs:1856-1862

Runtime events are remapped live

Text, thinking, tool starts/finishes, component render/unmount, and browser activity events are forwarded to AgentEventBus as AgentTurnEvent variants.

Source: crates/ocean-daemon/src/main.rs:1864-1973

Events

The daemon publishes the product vocabulary clients render.

Clients deserialize each SSE data: payload as one AgentTurnEvent JSON object.

event: session_created

data: {"type":"session_created", ...}


event: assistant_text_delta

data: {"type":"assistant_text_delta", ...}

Canonical variants

The SDK defines turn_started, assistant_text_delta, thinking_delta, tool_call_started, tool_call_chunk, tool_call_finished, turn_finished, session_created, component_render, component_unmount, browser_activity, and extension.

Source: crates/ocean-agent-sdk/src/lib.rs:277-389

Permissions and safety

The daemon is also the operator-control point.

Permission waits

Without blanket mutating permission, the daemon records a PermissionStatus, emits a PermissionRequest on the legacy bus, and waits on a one-shot decision or cancellation.

Source: crates/ocean-daemon/src/main.rs:505-588

Important implementation note

The product-shaped /v1/agent/turns path currently builds control with allow_mutating: true before calling the runtime. That means web/TUI halt controls are wired, but this path is operating in yolo-style permission mode today.

Source: crates/ocean-daemon/src/main.rs:1840-1851, :1977-1979

Known documentation gap

One mismatch to keep visible.

The root route is not the full contract

GET / advertises /health, /ready, legacy event/prompt/request/session routes, but omits the newer product routes such as /v1/agent/turns, /v1/agent/events, projects, models, components, and Longhouse. The router itself mounts them, so client documentation should prefer the source routes above until the root manifest is updated.

Advertised subset: crates/ocean-daemon/src/main.rs:230-248. Actual mounted routes: crates/ocean-daemon/src/main.rs:192-218.
