Ocean OS / Sessions + storage
slice 10 · sessions
local-first transcript memory

Sessions live in the daemon, bucketed by workspace and persisted as JSON.

Ocean clients are steering surfaces. The durable transcript is owned by ocean-agent inside ocean-os, written under the daemon config directory, scoped to a git/workspace root, and resumed by session id from any client that speaks the product API.

Evidence boundary

Session behavior is source-grounded; private session state is not public evidence.

A prior point-in-time check exposed a developer path, internal session title, branch, model, and counts. Those details were removed rather than presented as current product state.

Safe verification shape

Use an isolated fixture workspace, synthetic session titles, and redacted identifiers when demonstrating scoped session listing.

Privacy invariant

Session files may contain prompts, answers, reasoning text, and tool output. Public documentation must not embed real session records.

Storage object

A session file is provider history plus workspace metadata.

Session fields

Each persisted session has id, created/updated timestamps, model, provider, full ocean_protocol::Message history, optional workspace root, original cwd, git branch, and git commit.

Workspace binding

bind_workspace tags a session once from the caller's cwd. Existing values win so resuming from another directory does not rewrite the original workspace metadata.

Workspace root

Ocean tries git -C <cwd> rev-parse --show-toplevel first, then falls back to cwd when git is absent or the path is not inside a repo.

Write path

Turns load, run, cap, and atomically save.

01

Lock session

The runtime resolves or mints the session id, then holds a per-session async mutex across load → run → save so concurrent turns cannot overwrite each other's history.

Source: crates/ocean-agent/src/lib.rs:87-94, crates/ocean-agent/src/lib.rs:391-400

02

Resume strictly

A supplied-but-unknown session id errors by default. Creating a new transcript with a specific id requires explicit create_if_missing.

Source: crates/ocean-agent/src/lib.rs:402-416

03

Run with history

The session messages are replayed through the runtime, with new user prompt appended. OpenAI-compatible providers strip stored assistant thinking before replay because reasoning is output-only for them.

Source: crates/ocean-agent/src/lib.rs:418-450

04

Atomic save

After the run, Ocean caps stored history, pretty-serializes JSON to a sibling temp file, then renames it over the target so a crash mid-write cannot corrupt the previous transcript.

Source: crates/ocean-agent/src/lib.rs:532-538, crates/ocean-agent/src/lib.rs:1122-1139

History guardrails

Storage is bounded and replay-safe.

200-message cap

The stored transcript keeps at most MAX_SESSION_MESSAGES = 200. The runtime still trims per model context window, but this hard cap controls file size and reload cost across long-lived sessions.

Source: crates/ocean-agent/src/lib.rs:889-900

No orphan tool results

If trimming would leave a ToolResult as the first replayed message, Ocean drops leading orphan tool results so providers do not reject a tool result without its assistant tool call.

Source: crates/ocean-agent/src/lib.rs:901-908

Corruption is loud

load_resumable returns Ok(None) only when no file exists. If a matching file exists but cannot be read or parsed, it returns an error so Ocean does not silently wipe the transcript.

Source: crates/ocean-agent/src/lib.rs:1150-1167, crates/ocean-agent/src/lib.rs:1515-1523

Provider thinking replay

DeepSeek, OpenAI, Codex, OpenAI-compatible, MiniMax, and Kimi stored thinking is removed before replay. Anthropic signed thinking can remain in history.

Source: crates/ocean-agent/src/lib.rs:418-450, crates/ocean-agent/src/lib.rs:873-881

Why this matters

Session bugs are daemon bugs, not surface bugs.

Shared brain

The TUI, web Surface, CLI, browser side panel, and future native clients all reuse daemon-held session ids. A lost transcript or accidental fork affects every client because the storage layer is shared.

Current SDK bridge gap

The legacy/core session detail path is richer today than /v1/agent/sessions/{id}, whose SDK turn list is still empty. Product clients that need full replay currently hydrate from the core session detail route or their own live SSE state.
