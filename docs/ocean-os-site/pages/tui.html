Ocean OS / TUI cockpit
slice 7 · ocean-tui
terminal steering cockpit

The TUI is the operator cockpit for daemon sessions, rooms, tools, and live events.

ocean-tui is not a separate agent. It is a Ratatui/Crossterm client that talks to the same local daemon as Ocean Surface: it checks health/readiness, submits turns, streams SDK events, lists sessions, handles permissions, and gives the operator a keyboard-first PM room.

Binary shape

The TUI starts as either cockpit mode or mesh parity mode.

Default daemon cockpit

The CLI defaults to http://127.0.0.1:4780, overridable with --url or OCEAN_DAEMON_URL. The main command is ocean-tui; the project symlink is usually ocean.

Mesh subcommand

ocean-tui mesh is a read-only TIDES-MESH parity view over file-backed state, with tabs for board, events, inbox, and agents.

Daemon client

Every control path is an HTTP call into the daemon.

The TUI uses blocking reqwest clients in worker threads so the terminal event loop stays responsive.

TUI call
Daemon route
Use
health / ready
GET /health, GET /ready
Show daemon service/backend and provider/model readiness.
sessions, session_detail
GET /v1/sessions, GET /v1/sessions/{id}
List workspace-bound transcripts and resume a selected session.
agent_turn
POST /v1/agent/turns
Submit room-scoped PM/Writers/ORCH/Review prompts to the product API.

Show in-flight turns and halt the active one.
permissions, permission_decision
GET /v1/permissions, POST /v1/permissions/{id}/decision

Rooms

Function keys switch workspaces without changing the daemon brain.

Seven visible rooms

The cockpit has F1 PM, F2 Writers Room, F3 ORCH + MESH, F4 Review Room, F5 TideDash, F6 WorkOps, and F7 WorldMap.

Runtime rooms vs placeholders

Only F1-F4 map to daemon Track-0 room ids today: pm, writers, orch_mesh, and review. F5-F7 are visible provisional rooms; submitting there is intentionally a no-op status path.

PM rendering

The terminal has a structured transcript, not just raw text.

Blocks

The PM room stores each assistant turn as blocks: visible text, collapsed/expandable thinking, and tool calls with running/ok/error status. Thinking is collapsed by default and can be toggled with /thinking.

Source: crates/ocean-tui/src/main.rs:293-320, crates/ocean-tui/src/main.rs:2876-2901, crates/ocean-tui/src/main.rs:4552

Coalescing

Reasoning models can interleave thinking and content token-by-token, so the TUI coalesces visible deltas back into the last text block unless a structural boundary such as a tool call has occurred.

Source: crates/ocean-tui/src/main.rs:312-320

Tool timeline

Tool start, chunk, and finish events are summarized into a timeline and mirrored into PM blocks, giving the terminal the same streaming observability as web clients.

Source: crates/ocean-tui/src/main.rs:3051-3122, crates/ocean-tui/src/main.rs:1430-1437

Component limitation

The TUI notices component_render and component_unmount events, but it summarizes them as transcript lines. Rich component rendering belongs to the PWA/web surface.

Source: crates/ocean-tui/src/main.rs:3161-3178

Live status surfaces

The cockpit watches more than chat.

Sessions

/sessions and /resume let the operator list workspace/all sessions and select a transcript target. The selected session id is converted into AgentSessionId for future SDK turns.
