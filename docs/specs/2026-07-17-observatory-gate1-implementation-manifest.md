## 1. Event Schema and Type Definitions

### 1.1 Forbidden Field Compile-Time Enforcement

**Principle:** Redaction happens at the type level BEFORE serialization. Forbidden fields cannot exist in types that flow to durable storage or SSE broadcast.

**Forbidden fields (never serialized to Observatory, even if present in runtime AgentEvent):**
- Prompts, system instructions, user input
- Assistant thinking text, reasoning deltas, scratchpad
- Tool execution arguments (`tool_args`, `args`)
- Tool execution output (`tool_output`, `result`, `stdout`)
- Error messages, stack traces, raw exceptions
- Environment variables, paths, current working directory
- Request/response headers, authentication credentials, API keys
- Secrets, keys, tokens, passwords, session identifiers
- Raw permission reason text, approval/denial rationale
- Extension payloads, turn payloads, raw event data

**Strategy:** 
1. Define Observatory `EventPayload` enum with only safe variant fields — never include the forbidden list.
2. Map runtime `AgentEvent` variants to Observatory `EventPayload` variants, explicitly DROPPING forbidden fields during transformation.
3. Define `#[derive(Serialize)]` only on types that have been audited to exclude forbidden fields.
4. Use a compile-time redaction macro `#[observer_safe]` that: (a) prevents accidentally adding forbidden fields to a type, (b) generates a compile error if an unsafe type is derived Serialize, (c) documents the redaction decision per field.
5. Unit tests use a redaction property test fixture (section 1.8) that verifies every forbidden field is un-serializable when constructed in the actual type.

```rust
/// Monotonic daemon-allocated cursor. Opaque to clients; used for ordering and resumption.
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash, Serialize, Deserialize)]
pub struct Cursor(u64);

impl Cursor {
    /// Create a cursor from a u64 value (daemon-internal).
    pub fn new(inner: u64) -> Self {
        Cursor(inner)
    }
    
    /// Get the inner u64 value.
    pub fn into_inner(self) -> u64 {
        self.0
    }
    
    /// Serialize as a decimal string for wire format.
    /// E.g., Cursor(1842) → "1842"
    pub fn as_string(&self) -> String {
        self.0.to_string()
    }
    
    /// Parse from a decimal string wire format.
    /// Returns an error if the string is not a valid u64.
    pub fn from_string(s: &str) -> Result<Self, std::num::ParseIntError> {
        s.parse::<u64>().map(Cursor)
    }
}

impl std::fmt::Display for Cursor {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        write!(f, "{}", self.0)
    }
}
```

### 1.5 Compile-Time Redaction Macro (Sketch)

Define a `#[observer_safe]` attribute macro that:

1. Scans type fields for names in the forbidden list (see section 1.1).
2. Emits a compile error if a forbidden field is found.
3. Permits only types that can safely serialize without exposing forbidden content.
4. Documents the redaction rationale in generated code comments.

**Example:**
```rust
#[derive(Serialize, Deserialize)]
#[observer_safe]  // Compiles: no forbidden fields
pub struct EventPayload { ... }

#[derive(Serialize, Deserialize)]
#[observer_safe]  // Compile error: field `prompt` is forbidden
pub struct BadPayload {
    pub prompt: String,  // ERROR: forbidden field
}
```

**Implementation:** The macro is defined in a `crates/ocean-observatory/src/redaction_macro.rs` module and re-exported from `lib.rs`. It uses `proc_macro2` and `syn` to inspect fields at compile time.

## 2. Cursor Semantics

### 2.1 Cursor Allocation and Ordering

**Property 1: Monotonicity**
- Every new event appended to the durable log receives a cursor value strictly greater than the previous event's cursor.
- Cursors are u64 integers, starting from 1 at daemon startup.
- No gaps unless explicitly signaled (StreamGap events).

**Property 2: Daemon-Owned Allocation**
- Cursors are allocated ONLY by the daemon at the moment an event is appended to durable storage.
- Clients never allocate cursors.
- Extensions cannot request specific cursor values.

**Property 3: Wire Encoding**
- Internal representation: `u64` (opaque, 64-bit unsigned)
- Wire format: decimal string (e.g., "1842")
- Encoded in all JSON responses as a string field.
- HTTP headers and SSE `Last-Event-ID` use string format.

**Property 4: Gap Semantics**
- If a client resumes from cursor `C` and receives events from cursor `C+1`, `C+2`, ..., `C+N`, the events are consecutive (no gaps).
- If a gap is detected (e.g., cursor jumps from `C+5` to `C+10`), the daemon sends an explicit `StreamGap` event with `from_cursor` and `to_cursor` fields.
- A gap indicates: retention boundary crossed, daemon restart, or transient connectivity loss.
- The client must request a fresh snapshot after a gap to restore consistency.

```rust
    pub fn from_string(s: &str) -> Result<Self, std::num::ParseIntError> {

    pub fn next(self) -> Cursor {
        Cursor(self.0.saturating_add(1))

    pub fn is_consecutive_after(self, previous: Cursor) -> bool {
```

### 2.3 Daemon Startup Cursor Initialization

- At daemon startup, read the current maximum cursor from durable storage (or 0 if the store is new).
- Allocate the next cursor for the first event (DaemonStarted).
- Increment monotonically for every subsequent event.
- Never reuse or skip cursor values, even after a restart.

## 3. Authentication and Authorization

### 3.1 Token Format and Signing (Per R2: HMAC-SHA256)

**Token Structure:**
```
HMAC(SHA256, daemon_secret, payload) + "." + payload_base64
```

**Payload (JSON, base64-encoded):**
```json
{
  "principal": "observer",
  "scope": "observatory:summary",
  "daemon_instance_id": "<uuid>",
  "issued_at": 1721233351,  // Unix timestamp
  "expires_at": 1721233951,  // Unix timestamp (15-60 minutes)
  "nonce": "<random-hex-32>"
}
```

**Rationale:**
- HMAC-SHA256 provides cryptographic integrity without requiring asymmetric key infrastructure.
- Daemon-local secret is stored in `.ocean/observatory-secret` (mode 0600, 32 bytes random).
- Payload is self-contained and inspectable (no state lookup needed for validation).
- Nonce prevents replay attacks.
- Lifetime: 15-60 minutes. Default: 30 minutes. Configurable per environment.

### 3.2 Secret Storage

**File:** `.ocean/observatory-secret`
**Format:** 32 bytes of random binary data.
**Permissions:** mode 0600 (owner read-write only).
**Initialization:**
- If the file does not exist, the daemon generates a new 32-byte random secret and writes it during startup.
- If the file exists, the daemon reads and validates that it is exactly 32 bytes.
- The daemon never logs, prints, or embeds the secret in responses.

**Rotation:**
- To rotate the secret, the operator: (1) generates a new secret and overwrites `.ocean/observatory-secret`, (2) all existing tokens become invalid (clients must re-authenticate).

### 3.3 Scoped Observer Principals

**Scope `observatory:summary` (default, V1)**
- Observe topology, execution phases, coarse metrics, safe aliases, fixed reason codes.
- Cannot observe prompts, thinking, tool output, environment, paths, or secrets.
- Cannot approve permissions, cancel executions, or modify daemon state.

**Scope `observatory:content` (future, not V1)**
- Extends `observatory:summary` to include bounded content projection (prompts, output, reasoning).
- Requires separate explicit approval decision (privacy/encryption/export).
- Not implemented in V1; reserved for future.

**Scope `extension:<producer-id>` (future, not V1)**
- Observe only topology and events related to a specific extension producer.
- Allows delegated project observation without whole-daemon visibility.
- Not implemented in V1; reserved for future.

**Control scopes (intentionally absent in V1)**
- `observatory:control` — cancel executions, approve permissions, etc.
- Not implemented in V1; all mutations use existing authoritative routes.

### 3.4 Token Distribution

**First-party local web/Tauri path:**
- At boot the daemon mints a boot-bound `observatory:summary` token and atomically writes `.ocean/observatory-token` with mode 0600.
- The daemon replaces that file every ten minutes; tokens expire after thirty minutes, so existing streams survive rotation while new requests read the latest credential.
- The Ocean Surface proxy reads the token file immediately before opening an Observatory request or SSE stream and injects `Authorization: Bearer <token>` on the daemon-side hop.
- Browser JavaScript never receives the token, signing secret, or an issuance route. The proxy's existing operator authentication remains a separate outer boundary.

**CLI/native extension hosts:**
- A trusted local process reads `.ocean/observatory-token` immediately before its request and sends `Authorization: Bearer <token>`.
- `OCEAN_OBSERVER_TOKEN` remains an explicit operator override for isolated child processes; the daemon never injects it globally into arbitrary tool or shell subprocesses.
- The daemon signing secret remains only in `.ocean/observatory-secret` and is never distributed.

**No credential-issuance route:**
- V1 exposes no `/v1/observatory/token/*` route. The mode-0600 local token file is the only automatic first-party distribution seam.

**No Query-String Credentials:**
- Tokens are never embedded in URLs or query parameters.
- HTTP query strings can appear in logs, browser history, proxy logs, etc.
- Always use HTTP headers or cookies.

### 3.5 Token Validation (Daemon Side)

```rust
// Pseudo-code in auth.rs
pub fn validate_observer_token(token: &str, secret: &[u8; 32]) -> Result<TokenClaims, AuthError> {
    let parts: Vec<&str> = token.split('.').collect();
    if parts.len() != 2 {
        return Err(AuthError::InvalidFormat);
    }
    
    let received_hmac = parts[0];
    let payload_b64 = parts[1];
    
    // Decode payload
    let payload_json = base64_decode(payload_b64)?;
    let claims: TokenClaims = serde_json::from_str(&payload_json)?;
    
    // Verify HMAC
    let computed_hmac = hmac_sha256(secret, payload_json.as_bytes());
    if computed_hmac != base64_decode(received_hmac)? {
        return Err(AuthError::InvalidSignature);
    }
    
    // Check expiration
    let now = SystemTime::now()
        .duration_since(UNIX_EPOCH)?
        .as_secs();
    if now > claims.expires_at {
        return Err(AuthError::TokenExpired);
    }
    
    // Verify daemon instance
    if claims.daemon_instance_id != current_daemon_instance_id() {
        return Err(AuthError::WrongInstance);
    }
    
    Ok(claims)
}
```

## 4. SQLite/WAL Persistence Contract

### 4.1 Schema Design

**Database:** `.ocean/observatory.db` (SQLite 3)
**Configuration:** Enable WAL mode (`PRAGMA journal_mode = WAL`) for concurrent read/write safety.

```sql

    id INTEGER PRIMARY KEY AUTOINCREMENT,
    cursor INTEGER NOT NULL UNIQUE,
```

```rust
    /// Open or create the SQLite database.
    pub fn open(db_path: &Path, retention_policy: RetentionPolicy) -> Result<Self> {
        // Enable WAL mode, set other pragmas for safety
        let db = rusqlite::Connection::open(db_path)?;
        db.execute_batch(
            "PRAGMA journal_mode = WAL;
             PRAGMA synchronous = NORMAL;
             PRAGMA foreign_keys = ON;"
        )?;
        // Create tables if they don't exist
        db.execute_batch(SCHEMA)?;
        
        // Load current cursor from watermarks
        let current_cursor = Self::load_current_cursor(&db)?;
        
        Ok(ObservatoryStore {
            db,
            current_cursor: Arc::new(Mutex::new(current_cursor)),
            retention_policy,
        })
    }
    
    /// Append an event to the durable log atomically.
    /// Returns the assigned cursor.
    pub fn append_event(&self, mut envelope: EventEnvelope) -> Result<Cursor> {
        let cursor = {
            let mut c = self.current_cursor.lock().unwrap();
            *c = c.next();
            *c
        };
        
        envelope.cursor = cursor;
        
        let tx = self.db.transaction()?;
        {
            let payload_json = serde_json::to_string(&envelope.payload)?;
            tx.execute(
                "INSERT INTO observatory_events
                    (cursor, event_id, schema_version, created_at, kind, payload_json, producer_id, visibility)
                 VALUES (?1, ?2, ?3, ?4, ?5, ?6, ?7, ?8)",
                rusqlite::params![
                    cursor.into_inner(),
                    &envelope.event_id,
                    envelope.schema_version,
                    &envelope.recorded_at,
                    format!("{:?}", envelope.kind),
                    payload_json,
                    &envelope.producer.id,
                    format!("{:?}", envelope.visibility),
                ],
            )?;
            
            // Update execution node projection
            self.update_execution_node(&tx, &envelope)?;
            
            // Update watermark
            tx.execute(
                "INSERT OR REPLACE INTO watermarks (key, cursor, created_at)
                 VALUES ('snapshot_watermark', ?1, ?2)",
                rusqlite::params![cursor.into_inner(), &envelope.recorded_at],
            )?;
        }
        tx.commit()?;
        
        Ok(cursor)
    }
    
    /// Get a consistent snapshot at a specific cursor.
    pub fn snapshot_at(&self, cursor: Option<Cursor>) -> Result<Snapshot> {
        let cursor = cursor.unwrap_or_else(|| {
            self.db.query_row(
                "SELECT cursor FROM watermarks WHERE key = 'snapshot_watermark'",
                [],
                |row| row.get::<_, u64>(0).map(Cursor::new),
            ).unwrap_or(Cursor::new(0))
        });
        
        // Transactionally load all nodes and edges as of cursor
        let mut stmt = self.db.prepare(
            "SELECT execution_id, root_execution_id, parent_execution_id, phase, created_at
             FROM execution_nodes
             WHERE first_cursor <= ?1
             ORDER BY first_cursor"
        )?;
        
        let nodes = stmt.query_map([cursor.into_inner()], |row| {
            Ok((
                row.get::<_, String>(0)?,
                row.get::<_, String>(1)?,
                row.get::<_, Option<String>>(2)?,
                row.get::<_, String>(3)?,
                row.get::<_, String>(4)?,
            ))
        })?
        .collect::<Result<Vec<_>, _>>()?;
        
        // Similar for edges
        let mut edges_stmt = self.db.prepare(
            "SELECT edge_id, parent_execution_id, child_execution_id, created_at
             FROM execution_edges
             WHERE created_at <= ?1"
        )?;
        
        let edges = edges_stmt.query_map([&cursor.to_string()], |row| {
            Ok((
                row.get::<_, String>(0)?,
                row.get::<_, String>(1)?,
                row.get::<_, String>(2)?,
                row.get::<_, String>(3)?,
            ))
        })?
        .collect::<Result<Vec<_>, _>>()?;
        
        Ok(Snapshot {
            watermark_cursor: cursor,
            nodes,
            edges,
            earliest_available_cursor: self.earliest_cursor()?,
        })
    }
    
    /// Retrieve events after a cursor (for tail streaming).
    pub fn events_after(&self, cursor: Cursor, limit: Option<usize>) -> Result<Vec<EventEnvelope>> {

             FROM observatory_events
             WHERE cursor > ?1
             ORDER BY cursor ASC
             LIMIT ?2"
        )?;
        
        let events = stmt.query_map([cursor.into_inner(), limit as u64], |row| {
            // Reconstruct EventEnvelope from row
            // ... deserialization logic
        })?
        .collect::<Result<Vec<_>, _>>()?;
        
        Ok(events)
    }
    
    /// Retrieve paginated events for replay.
    pub fn events_page(
        &self,
        after: Cursor,
        through: Option<Cursor>,
        limit: usize,
    ) -> Result<EventsPage> {
        let through = through.unwrap_or_else(|| {
            self.db.query_row(
                "SELECT cursor FROM watermarks WHERE key = 'snapshot_watermark'",
                [],
                |row| row.get::<_, u64>(0).map(Cursor::new),
            ).unwrap_or(Cursor::new(0))
        });
        
        let limit = limit.min(10000);  // Cap at 10k
        
        let mut stmt = self.db.prepare(
            "SELECT cursor, event_id, ... FROM observatory_events
             WHERE cursor > ?1 AND cursor <= ?2
             ORDER BY cursor ASC
             LIMIT ?3"
        )?;
        
        let events = stmt.query_map([after.into_inner(), through.into_inner(), limit as u64], ...)?
            .collect::<Result<Vec<_>, _>>()?;
        
        let next_after = events.last().map(|e| e.cursor);
        let has_more = events.len() == limit;
        
        Ok(EventsPage {
            events,
            next_after,
            has_more,
            complete: through == self.latest_cursor()?,
        })
    }
    
    /// Apply retention policy and prune old events.
    pub fn apply_retention(&self) -> Result<usize> {
        let policy = &self.retention_policy;
        let now = SystemTime::now();
        
        // Calculate boundary: 7 days ago or 1 GiB limit
        let cutoff_time = now - Duration::from_secs(7 * 24 * 60 * 60);
        let cutoff_cursor = self.cursor_before_time(cutoff_time)?;
        
        // Don't prune nonterminal nodes
        let mut stmt = self.db.prepare(
            "SELECT MIN(first_cursor) FROM execution_nodes WHERE phase != 'finished' AND phase != 'error'"
        )?;
        let nonterminal_min_cursor: Option<u64> = stmt.query_row([], |row| row.get(0))?;
        
        let safe_cutoff = if let Some(nc) = nonterminal_min_cursor {
            cutoff_cursor.min(Cursor::new(nc.saturating_sub(1)))
        } else {
            cutoff_cursor
        };
        
        // Prune events, record in retention_archive
        let tx = self.db.transaction()?;
        let count = tx.execute(
            "DELETE FROM observatory_events WHERE cursor <= ?1",
            [safe_cutoff.into_inner()],
        )?;
        
        tx.execute(
            "INSERT INTO retention_archive (pruned_at, from_cursor, to_cursor, count_events)
             VALUES (?1, ?2, ?3, ?4)",
            rusqlite::params![
                now.duration_since(UNIX_EPOCH)?.as_secs(),
                0,
                safe_cutoff.into_inner(),
                count,
            ],
        )?;
        
        tx.commit()?;
        
        Ok(count)
    }
}

    pub earliest_available_cursor: Cursor,

    pub has_more: bool,
    pub complete: bool,
}
```

### 4.3 Concurrency Model

**Read/Write Safety:**
- WAL mode ensures concurrent readers do not block writers.
- Each `append_event` uses a SQLite transaction (atomic insert of event + node/edge projections).
- Multiple daemon threads can call `append_event` concurrently; SQLite's locking ensures serialization.
- Snapshot and replay queries open separate read transactions; they do not see uncommitted appends.

**Checkpoint and WAL Cleanup:**
- The daemon runs automatic WAL checkpoints every 60 seconds or when the WAL exceeds 16 MiB.
- Operator can trigger manual checkpoint via a health endpoint (future).
- WAL files are automatically cleaned up after checkpoint.

**Connection Pooling:**
- The `ObservatoryStore` maintains a single `rusqlite::Connection` wrapped in `Arc<Mutex<>>`.
- Multiple threads acquire the mutex briefly for a transaction or query, then release.
- This is sufficient for typical single-daemon deployments; if connection pooling is needed later, use `sqlx` or `r2d2`.

## 5. Extension Admission and Binding Contract

### 5.1 Admission Request and Response

**Admission happens in two phases:**

**Phase 1: Request (Extension → Daemon)**

```http
POST /v1/observatory/admission/request
Content-Type: application/json
Authorization: Bearer <extension-producer-token>

{
  "parent_execution_id": "<uuid>",
  "root_execution_id": "<uuid>",
  "labels": ["training_job", "batch_123"],
  "producer_id": "my-orchestration-extension",
  "lease_duration_seconds": 3600,
  "idempotency_key": "<uuid>"
}
```

**Response (Daemon → Extension)**

```json
{
  "execution_id": "<uuid>",
  "edge_id": "<uuid>",
  "binding_token": "<256-bit-random-hex>",
  "token_ttl_seconds": 30
}
```

**Validation Rules (Daemon side):**
1. Parent execution must exist and be in a `running` or `admitted` phase.
2. No cycles: child cannot have parent as descendant.
3. Depth limit: execution tree depth ≤ 32 levels.
4. Cross-authority: child parent_root must match parent root_execution_id.
5. Idempotency: if idempotency_key matches a previous request, return the same execution_id + edge_id + NEW binding_token.
6. Producer must have the `extension:<producer-id>` scope.

**Rejection Responses:**

```json
{
  "error": "cycle_detected",
  "message": "Parent is a descendant of this execution",
  "http_status": 400
}
```

```json
{
  "error": "depth_exceeded",
  "message": "Execution tree depth would exceed 32 levels",
  "http_status": 400
}
```

```json
{
  "error": "invalid_parent",
  "message": "Parent execution not found or in wrong phase",
  "http_status": 400
}
```

### 5.2 Binding Phase

**Phase 2: Binding (Extension → Daemon via ordinary turn)**

After receiving a binding token, the extension submits an ordinary daemon turn with an additive `_observation_binding` field:

```json
{
  "action": "turn",
  "session_id": "...",
  "turn_id": "...",
  "request_id": "...",
  "messages": [...],
  "_observation_binding": {
    "execution_id": "<from admission response>",
    "binding_token": "<from admission response>"
  }
}
```

**Daemon Processing:**
1. Validate binding_token: must be valid, not expired (< 30s old), and match the execution_id.
2. Consume the token (mark as used, cannot reuse).
3. Record an `ExecutionAdmitted` event in Observatory.
4. Remove the `_observation_binding` field before prompt/provider serialization.
5. Proceed with normal turn execution.

**Binding Token Properties:**
- Format: 256 bits (64 hex characters) of cryptographically secure random data.
- Lifetime: 30 seconds from issuance. After expiry, the extension must re-request admission.
- Storage: in-memory only. Never persisted to disk, logs, or Observatory.
- Invalidation: automatically expires after 30s; can be manually revoked by the daemon.
- No replay: once consumed, the token is deleted and cannot be reused.

### 5.3 Validation Contract

```rust
// In crates/ocean-observatory/src/admission.rs

pub struct AdmissionRequest {
    pub parent_execution_id: String,
    pub root_execution_id: String,
    pub labels: Vec<String>,
    pub producer_id: String,
    pub lease_duration_seconds: u32,
    pub idempotency_key: String,
}

pub struct AdmissionResult {
    pub execution_id: String,
    pub edge_id: String,
    pub binding_token: String,
    pub token_ttl_seconds: u32,  // Always 30
}

pub fn validate_admission_request(
    req: &AdmissionRequest,
    store: &ObservatoryStore,
    config: &AdmissionConfig,
) -> Result<AdmissionResult, AdmissionError> {
    // 1. Check parent exists and is in valid phase
    let parent_node = store.execution_node(&req.parent_execution_id)?;
    if !matches!(parent_node.phase, ExecutionPhase::Admitted | ExecutionPhase::Running) {
        return Err(AdmissionError::InvalidParentPhase);
    }
    
    // 2. Check for cycles
    if is_ancestor(store, &req.root_execution_id, &req.parent_execution_id)? {
        return Err(AdmissionError::CycleDetected);
    }
    
    // 3. Check depth
    let depth = calculate_tree_depth(store, &req.root_execution_id)?;
    if depth >= config.max_execution_depth {
        return Err(AdmissionError::DepthExceeded);
    }
    
    // 4. Check idempotency
    if let Some(previous) = store.previous_admission_by_key(&req.idempotency_key)? {
        // Return the same IDs but a fresh token
        return Ok(AdmissionResult {
            execution_id: previous.execution_id,
            edge_id: previous.edge_id,
            binding_token: generate_binding_token(),
            token_ttl_seconds: 30,
        });
    }
    
    // 5. All valid: allocate IDs and token
    let execution_id = uuid::Uuid::new_v4().to_string();
    let edge_id = uuid::Uuid::new_v4().to_string();
    let binding_token = generate_binding_token();
    
    // Record admission metadata (not durable until binding is consumed)
    store.record_pending_admission(AdmissionRecord {
        execution_id,
        parent_execution_id: req.parent_execution_id.clone(),
        edge_id,
        binding_token: binding_token.clone(),
        issued_at: SystemTime::now(),
        idempotency_key: req.idempotency_key.clone(),
    })?;
    
    Ok(AdmissionResult {
        execution_id,
        edge_id,
        binding_token,
        token_ttl_seconds: 30,
    })
}

pub fn validate_binding(
    token: &str,
    execution_id: &str,
    store: &ObservatoryStore,
) -> Result<(), BindingError> {
    // 1. Retrieve the pending admission by execution_id
    let record = store.pending_admission(&execution_id)?;
    
    // 2. Check token matches and is not expired
    if record.binding_token != token {
        return Err(BindingError::TokenMismatch);
    }
    if SystemTime::now().duration_since(record.issued_at)? > Duration::from_secs(30) {
        return Err(BindingError::TokenExpired);
    }
    
    // 3. Token is valid; will be consumed before prompt serialization
    Ok(())
}

fn generate_binding_token() -> String {
    use rand::RngCore;
    let mut rng = rand::thread_rng();
    let mut bytes = [0u8; 32];
    rng.fill_bytes(&mut bytes);
    hex::encode(bytes)
}
```

### 7.2 GET /v1/observatory/events (Server-Sent Events)

**Purpose:** Stream new events after a cursor using SSE. Allows live observation with resume support.

**Request:**


**Query Parameters:**
- `after` (optional, string cursor): resume after this cursor. Defaults to latest.
- `scope` (optional, enum): `summary` (default) or future `content`.

**Headers:**
- `Last-Event-ID`: SSE standard; client sends the last event ID it received. Daemon resumes after this cursor.

**Response (200 OK, text/event-stream):**

```
data: {"cursor":"1843","event_id":"uuid","kind":"execution.admitted","payload":{...}}
id: 1843

data: {"cursor":"1844","event_id":"uuid","kind":"tool.started","payload":{...}}
id: 1844

id: 1844

data: {"cursor":"1845","event_id":"uuid","kind":"stream.gap","payload":{"from_cursor":"1844","to_cursor":"1850","reason":"retention_boundary"}}
id: 1845
```

**Event Format:**
- SSE `data` field: JSON EventEnvelope
- SSE `id` field: cursor (string), allows browser/client to resume via `Last-Event-ID`
- Heartbeat (comment lines starting with `:`) every 30 seconds if no events

**Error Responses:**

**401 Unauthorized (during streaming):**
```
data: {"error":"unauthorized","message":"Token revoked or expired"}
event: error
id: <current-cursor>
```

**410 Gone (cursor expired):**
```
data: {"error":"cursor_expired","message":"Cursor is before retention boundary. Request fresh snapshot.","earliest_cursor":"100"}
event: reset
id: <boundary-cursor>
```

**400 Bad Request (malformed cursor):**
```
data: {"error":"invalid_cursor","message":"Cursor format invalid"}
event: error
```

**Client Behavior on Error:**
1. On `error` event: log and close connection (retry after backoff).
2. On `reset` event: request fresh snapshot, then resume streaming from new watermark.
3. On `stream.gap` event: data is still valid; cursor has jumped; future events continue.

- `after` (required, string cursor): start after this cursor
- `through` (optional, string cursor): end before/at this cursor (defaults to latest)
- `limit` (optional, integer 1–10000): max events per page (default 1000)
- `filter` (optional, string): filter expression: `kind:<event-kind>`, `producer:<producer-id>`, etc. (future)

**Response (200 OK):**

```json
{
  "events": [
    {
      "cursor": "1843",
      "event_id": "uuid",
      "schema_version": 1,
      "occurred_at": "2026-07-17T18:02:31.234Z",
      "recorded_at": "2026-07-17T18:02:31.236Z",
      "kind": "execution.admitted",
      "truth": "host_observed",
      "producer": { "kind": "daemon", "id": "ocean-daemon" },
      "topology": { ... },
      "correlation": { ... },
      "visibility": "metadata",
      "payload": { ... }
    }
  ],
  "next_after": "1850",
  "has_more": true,
  "complete": false,
  "continuation_url": "/v1/observatory/replay?after=1850&through=2000&limit=1000"
}
```

**Pagination:**
- `next_after`: cursor to use in the next request's `after` parameter
- `has_more`: true if there are more events after `next_after`
- `complete`: true if this page reaches the `through` cursor or latest watermark

**Error Responses:**

**410 Gone (cursor range crosses retention boundary):**
```json
{
  "error": "retention_boundary_crossed",
  "message": "Events from cursor 50 to 100 are not available",
  "gap_from": "50",
  "gap_to": "99",
  "earliest_available": "100",
  "http_status": 410
}
```

**400 Bad Request:**
```json
{
  "error": "invalid_range",
  "message": "after >= through",
  "http_status": 400
}
```

### 7.4 Common Response Headers

All Observatory routes include:

```
Cache-Control: no-store, no-cache, must-revalidate, private
Pragma: no-cache
Expires: 0
Content-Type: application/json (or text/event-stream for /events)
X-Observatory-Cursor: <current-watermark-cursor>
X-Observatory-Instance: <daemon-instance-id>
```

## 8. Per-Task Test Requirements

### Task 2: Schema + Store + Redaction + Cursor (ocean-observatory crate)

**Required Tests:**
1. **Cursor tests** (src/cursor.rs):
   - Serialize/deserialize to/from decimal string
   - Monotonic increment (next())
   - Consecutive check (is_consecutive_after())
   - Overflow behavior (saturating_add)

2. **Redaction tests** (tests/redaction_tests.rs):
   - Every forbidden field mapping (section 6.2) has a test
   - Verify that EventPayload cannot serialize forbidden fields
   - Test that ThinkingDelta and other unsafe kinds are rejected

3. **Store tests** (tests/store_tests.rs):
   - Open/create database
   - Append event (atomicity, cursor increment)
   - Read snapshot at cursor
   - Events after cursor
   - Paginated replay
   - Retention pruning (respects nonterminal nodes)
   - Concurrent append from multiple threads
   - WAL checkpoint behavior

4. **Schema tests**:
   - Verify all CREATE TABLE statements execute without error
   - Verify indexes are created
   - Verify foreign key constraints are enforced

**Coverage Target:** ≥90%

**Command:** `cargo test -p ocean-observatory`

### Task 3: Admission + Binding (admission.rs, binding.rs)

**Required Tests:**
1. **Validation tests**:
   - Valid admission request (new execution, idempotent re-request, returns same IDs)
   - Reject invalid parent (not found, wrong phase)
   - Reject cycle (child cannot have parent as ancestor)
   - Reject depth exceeded (tree depth > 32)
   - Reject cross-authority parent (mismatched root_execution_id)

2. **Token lifecycle tests**:
   - Generate binding token (256 bits, hex)
   - Token consumed (marked used, cannot reuse)
   - Token expires after 30 seconds
   - Manual revocation

3. **Edge case tests**:
   - Multiple children of same parent
   - Rapid sequential admissions (concurrent thread safety)
   - Idempotency key collision (return cached result, fresh token)

**Coverage Target:** ≥90%

**Command:** `cargo test -p ocean-observatory admission`

### Task 4: Auth Middleware (auth.rs, Axum middleware in ocean-daemon)

**Required Tests:**
1. **Token generation tests**:
   - HMAC-SHA256 signing

   - Expiry calculation

2. **Token validation tests**:
   - Valid token (correct HMAC, not expired, correct daemon instance)
   - Invalid HMAC (rejection)
   - Expired token (rejection)
   - Wrong daemon instance (rejection)
   - Malformed token (not two parts, not valid base64)

3. **Middleware tests**:
   - Extract token from Authorization header

4. **Integration tests**:
   - Boot-bound summary token is atomically written to `.ocean/observatory-token` with mode 0600

**Coverage Target:** ≥90%

**Command:** `cargo test -p ocean-daemon auth`

## 10. Non-Acceptance Conditions

This manifest is not accepted if:

1. **Compile-time redaction macro cannot be implemented** (proof of concept required)
2. **Cursor monotonicity cannot be proven** (proof sketch required before acceptance)
3. **HMAC-SHA256 token implementation is incorrect or uses wrong key/payload**

5. **Forbidden field list is missing a known PII/credential category**
6. **SQLite schema has race conditions or data integrity gaps**
7. **API response formats deviate from this spec without operator approval**
8. **Tests are missing or have <90% coverage**

If any of these conditions arise during implementation, the task blocks and a revision of this manifest is required before proceeding.
